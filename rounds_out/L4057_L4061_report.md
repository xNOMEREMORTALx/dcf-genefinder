## L4057: simulated environments as filters (3 of 3; theory gate passed)
**Model.**
- **Small room:** 3 × 4 × 2.5 m, image-source echoes; total echo energy is 8.1× the direct sound.
- **Pipe:** 1 m, closed at one end, resonances at 85.75, 257, 429 Hz…; Q = 30 (a model assumption).
- **Noise:** microphone noise added after the environment.

| test | result |
|---|---|
| **Gate:** can a software filter create information? | **No.** Wiener dereverberation followed by a dry matched filter is 4.6 dB *worse* than the environment-aware matched filter, as theory requires |
| A1 dereverberation (speech-like bursts, 20 dB SNR, known room response) | correlation with the clean source **0.43 → 0.98** |
| A2 detecting a known chirp: template that includes the room's own echoes vs the dry template | **+6.1 dB** |
| A3 the pipe as a pre-amplifier: tone on the first resonance vs off resonance / vs no pipe | **41 dB / 29 dB** less source level needed |

**What this means for "fringe information":**
- **Knowing the environment helps in two ways.**
  - It restores *shape*: dereverberation undoes the room.
  - It sharpens *detection*: the room's echoes are part of the signal, so a template that includes them collects that energy.
- **Neither adds information.** No inverse filter beats the environment-aware matched filter.
- **The only true gain is physical:** a resonator (pipe, cavity, or a visual-mic object at its own mechanical resonance) amplifies its modes *before* the sensor's noise is added.
- **That gain is narrow-band and depends on Q.** The 29 dB follows from the Q = 30 assumption, so a real pipe must be measured.

## L4061: what happens between frames (3 of 4)
**Setup.**
- **Video:** synthetic, 240 fps, 120 rows read over 90% of each frame period, 0.3-pixel vibration, 2 DN noise.
- **Pipeline:** the real `dcf_visualmic` pipeline, with ROLLING mode switched on for the first time (H4 had flagged it "untested").

| test | result |
|---|---|
| R1 530 Hz vibration (frame Nyquist only 120 Hz), rolling mode | peak **530.11 Hz** ✔, but waveform correlation **0.71** (needed ≥ 0.8) → **FAIL** |
| R2 the same video read as whole frames | peak at the alias **50.0 Hz**, as predicted |
| R3 1,530 Hz, rolling mode | peak **1,529.8 Hz** |
| R4 row timing mis-set (0.8 instead of 0.9) | peak moves to **1,680 Hz**: the row timing must be calibrated per phone |

**Meaning.**
- **The rolling shutter recovers motion far above the frame rate's limit:** about 28,800 row samples per second at 240 fps.
- **Frequency comes through cleanly; waveform shape is only partly recovered** (r = 0.71). Two likely causes:
  - the reference frame carries its own row skew;
  - interpolation across the 10% dead time between frames.
- **Calibration is simple:** film a known tone once, then adjust ROW_FRACTION until the peak lands on it.

## On "photon movement" (time of flight)
- **Timing photons in flight needs picosecond detectors.** Light travels about 30 cm per nanosecond, so a phone camera cannot do it.
- **What ordinary cameras can do is read scattered light passively.** Computational periscopy (Saunders, Murray-Bruce & Goyal, Nature 565:472, 2019) images around a corner from the penumbra an object casts on a diffuse wall, using one ordinary photograph.

## Summary
- **Environment knowledge (room or pipe) restores waveform shape and sharpens detection,** but no software filter creates information.
- **A physical resonator is a real pre-amplifier** at its own resonant frequencies.
- **The rolling shutter sees between frames:** 530 Hz and 1,530 Hz recovered at 240 fps, provided the row timing is calibrated.
