## L4065: the rolling shutter, calibrated and fixed (5 of 5)
- **Auto-calibration works.** Film a *known* tone once and the tool finds the phone's row timing:
  - 0.89 for a true 0.90 (K1);
  - 0.73 for a true 0.75 (K2, boundary);
  - 0.81 for a true 0.80 in the end-to-end check of the shipped code (not graded).
  - Accuracy is about ±0.02.
- **Calibration carries over to new videos.** A second video from the K2 "phone" recovered an unknown 1,130 Hz tone at 1,130.15 Hz (K3).
- **The waveform problem is solved.**
  - With a median reference (first 31 frames), correlation with the true motion rose from **0.71 to 0.99** (W1).
  - With the old single-frame reference it stayed at 0.71 (W2): the loss came from the first frame's own rolling skew, not from the gaps between frames.
- **Shipped:**
  - `dcf_visualmic.py`: median reference by default in rolling mode, plus `CALIBRATE_TONE_HZ`;
  - **phone bundle 6.22**: menu 38 asks for rolling mode and a calibration tone (self-test 270/270).

## L4069: which way does the anchor test lean in real data? (2 of 3)
**Design:** synthetic genomes where longer genes sit at anchors **less** (the real direction, L3853); test genes from the long tail; 200 null runs.

**Results:**
- **D1 PASS.** Excess-side false positives were 8/200 (4%), so in the real direction the excess p-values are not inflated.
- **D3 PASS.** The members-minus-controls length gap persists (0.072 SD).
- **D2 FAIL.** I predicted the mismatch would leak into the deficit side (≥ 16/200); it gave 5/200 (2.5%).

**Reading.**
- **Over-rejection depends on direction.** It appears when the confounder pushes the same way as the tested effect (10.7% in L4037–L4053) and not when it pushes against it.
- **For Manuscript 3 this is reassuring.** Real long genes sit at anchors less, so the K⁺ *excess* p-values are, if anything, conservative.
- **It still does not replace the placebo-family calibration on the real files.**

## L4073: the frameshift detector on a small genome (4 of 4)
**Setup:** development candidate `dev/dcf_genefinder_v2.33dev_smallfs.py`, with one change: the scan runs from 100 kb instead of 500 kb. Tested on the *Arabidopsis* chloroplast.

**Results:**
- **F1 It runs.**
- **F2 It is honestly calibrated.** Recall 3.7% (6 of 161 simulated indels in genes) lies inside its own printed interval (1–27%).
- **F3 Every reported position was real** (6/6).
- **F4 Only one candidate** on the error-free genome.

**But sensitivity on a small genome is low.** The per-megabase rate caps allow only about 2 reports per 154 kb.
- **Release candidate for v2.33:** lower the limit. Report it as a high-precision, low-recall flag, not as an error finder.

## L4081: the corner camera in simulation (2 of 4)
**Setup:** 2-D model; a hidden scene of 48 patches; a diffuse wall of 200 pixels; an optional small occluder between them.

**Results:**
- **P1 PASS.** The occluder cuts the transport matrix's condition number about 35,000× (8.6×10¹⁶ → 2.4×10¹²) and raises its effective rank from 3 to 29. The wall becomes a camera, as the 2019 *Nature* paper describes.
- **P3 PASS.** Error with the occluder at 1% noise is 0.20, below the 0.5 bound.
- **P2, P4 FAIL.** The reconstruction error improved only 1.21× at 1% noise and 1.04× at 10%.
  - **Why:** my Gaussian prior fills in most of a four-block scene even without the occluder, so this error metric hides the gain.
  - The right test is resolution: can two nearby edges be told apart?

## Summary
- **The phone visual microphone now sees between frames reliably.** Rolling mode recovers tones far above the frame rate, calibrates its own row timing from one known tone, and reproduces waveforms at r = 0.99. It ships as bundle 6.22.
- **In the real confounder direction the anchor test does not inflate excess p-values,** which is reassuring for Manuscript 3; placebo calibration on real data is still owed.
- **The frameshift detector can run on small genomes,** honestly calibrated and precise, but finds few errors there.
- **An occluder makes a wall a camera mathematically,** but my error measure under-shows it; a resolution test comes next.
